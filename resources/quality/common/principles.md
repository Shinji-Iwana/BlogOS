# 共通基準：基本原則

**共通基準バージョン:** 1.0.0
**最終更新日:** 2026-09-24

## 1. 適用範囲

共通基準は、BlogOSで管理するすべてのブログの、次の記事に適用する。

* 新規記事
* 既存記事の改修

記事の種類（ロードマップ、集客記事など）は、ブログ別の定義で定める。

## 2. 基本原則

記事を作成・改修する際は、すべてのルールより先に以下の原則を守る。この基準に書かれていない内容は、原則に基づいて判断する。

### 原則1　正確性

記事の内容は正確でなければならない。推測や曖昧な情報で書かない。情報は次の順で採用する。

1. 実際の動作検証の結果
2. 公式ドキュメント
3. 信頼性の高い情報
4. 一般的な知見

誤った情報や古い情報を見つけた場合は、他の改善より先に修正する。

### 原則2　読者の理解

記事は、検索エンジンではなく読者の理解を優先する。SEOは重要だが、読者の理解を妨げるSEO施策は採用しない。想定読者（ブログ別の定義）が理解できるかを判断の基準とする。

### 原則3　理解重視

答えだけでなく、「なぜそうなるのか」まで理解できることを目指す。理由・背景・注意点・よくある勘違いまで説明する。

### 原則4　実践重視

読者が記事を読みながら実際に試せる・行動できる内容にする。

### 原則5　長期価値

一時的なアクセスではなく、数年後も価値がある記事を目指す。仕様変更などが起きた場合は、記事を更新して価値を保つ。

### 原則6　一貫性

記事ごとに品質や書き方を変えない。説明の方法、見出しの構成、図解、用語の説明を、ブログ全体で統一する。

### 原則7　体系性

記事を単体ではなく、ブログ全体の中で役割を持つものとして設計する。読者が次に読む記事へ自然に進める構成にする。

### 原則8　品質優先

作業時間や文字数より品質を優先する。合格基準（`scoring.md`）に満たない記事は完成とせず、不足点を改善する。

## 3. 判断の優先順位

判断に迷った場合は、次の順で優先する（D-06-05）。この優先順位は本節だけで定義し、他のファイルは本節を参照する。

1. 正確性
2. 読者の理解（ブログ別の定義で定めた想定読者）
3. 品質の点数（`scoring.md`）
4. SEO
5. ブログ全体の統一性
6. 収益

品質より収益を優先してはならない。

## 4. この基準より優先されるもの

次の場合は、この基準より優先して対応し、その後この基準自体を更新する。

* 技術仕様・製品・サービスの仕様変更
* セキュリティに関する重要な更新
* 検索エンジンのアルゴリズムの大幅な変更

## 5. KPIの考え方

記事の品質、読者満足度、SEO、サイト内の回遊、収益を総合的に評価し、いずれか1つだけを優先した改善は行わない。読者満足度を保った結果として、SEO・回遊・収益が向上する運営を基本とする。

具体的な確認指標は、ブログ別の定義で定める。
