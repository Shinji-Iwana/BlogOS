# 共通基準：必須条件・採点・判定

**共通基準バージョン:** 2.0.0
**最終更新日:** 2026-10-03

## 1. 判定の仕組み

記事は、次の4層で評価する（D-06-02、D-47）。

| 層 | 内容 | 使い方 |
| --- | --- | --- |
| ① 公開の条件 | 必須条件（2章）と、記事の型の必須（★）の項目（ブログ別の定義） | 1つでも満たさなければ、点数に関係なく公開不可 |
| ② 総合品質 | 100点満点（3章の項目の合計）。95点以上が合格 | 公開してよい完成度か |
| ③ 観点ごとの適合度 | ②と同じ判定を、観点ごとに集計した割合（4章） | どこを直せば伸びるか。合否には使わない |
| ④ 実績 | Search Console・GA4 の数字 | 点数にしない。③と比べて、次にやることを決める |

公開できるのは、人が確定した評価で、①をすべて満たし、かつ95点以上の場合だけである（D-07-03）。

## 2. 必須条件

| キー | 条件 | 判定者 |
| --- | --- | --- |
| `req.no_misinformation` | 誤った情報・古い情報がない | 人（AIは指摘のみ） |
| `req.no_speculation` | 根拠のない推測・断定で書いていない | AI・人 |
| `req.verified` | 掲載したコード・手順・操作は、実際に動作を確認している | 人 |
| `req.title_match` | タイトルで約束した内容を本文で解決している | AI・人 |
| `req.not_orphan` | ブログの構造の中に位置付けられ、どこからもリンクされない孤立記事ではない | AI・人（BlogOSの内部リンク情報を使う） |

ブログ別の定義で、必須条件を追加できる。共通の必須条件を外すことはできない。ただし、`req.verified` と `req.not_orphan` は、ブログの性質上該当しない場合に限り、ブログ別の定義で「対象外」にできる。

## 3. 採点項目

* 各項目を ○（満たしている）・△（一部不足）・×（満たしていない）の3段階で判定する。「判定の基準」は ○ と △ の条件で、どちらにも当てはまらなければ × とする。
* 「判定者」が「人」の項目は、BlogOSのAI機能では判定せず「要人間確認」とする（D-07-03）。
* キーは、評価結果（`article_evaluation_details.item_key`）に記録する値である（D-06-08）。
* 「観点」は、その項目の判定を集計する観点のキー（4章）。

### ② 記事の型（15点）

記事の型ごとの項目で採点する。項目・配点・判定の基準・必須（★）は、ブログ別の定義（例：`blogs/si-note/article-types.md` 6章）で決める。合計は15点とする。★の項目が × の記事は、点数に関係なく公開不可とする（1章 ①）。記事の型の項目は、すべて観点 `type` に集計する。

## 4. 観点

| キー | 観点 | 何を見るか |
| --- | --- | --- |
| `intent` | 検索意図 | 検索した人の目的を解決しているか |
| `type` | 記事の型 | 記事の型として欠けがないか（② の項目） |
| `people` | People-first | 役に立つか・独自性・経験・正確さ・信頼性（Google の考え方への適合。Google の評価そのものではない） |
| `seo` | SEO | 検索エンジンが内容を理解しやすいか（見出し・キーワード・内部リンク） |
| `ctr` | 検索結果で選ばれるか | タイトル・メタディスクリプションで、検索した人が「読みたい」と思えるか |
| `reader` | 理解しやすさ | 用語・図・例・つまずく点 |
| `ux` | 読みやすさ | 段落・箇条書き・配置 |
| `nav` | 回遊 | ロードマップ・関連記事・次に読む記事への導線 |
| `mon` | 収益化 | 合う教材を、邪魔にならない位置で、理由つきで紹介しているか |

* 観点の適合度（%）＝ その観点に関係する項目の得点の合計 ÷ 配点の合計 × 100（小数第1位まで）。
* 1つの項目は、関係するすべての観点に、同じ得点で数える（判定は1回だけ）。
* 対象外の項目と、要人間確認の項目は、観点の計算から除く。
* 観点の適合度は、合否に使わない。記事種類ごとの重要度（ブログ別の定義）で、改善の指摘の優先度を決める。

## 5. 点数の計算

* ○ は配点どおり、△ は配点の50%（**切り上げない**。0.5点単位）、× は0点とする（D-06-03）。
* 対象外とした項目は、配点から除外し、残りの項目の満点を100点に換算する。

  点数 = 対象項目の得点の合計 ÷ 対象項目の配点の合計 × 100（小数第2位を切り捨て、小数第1位まで）

* 対象外は、次の2つの単位で定める（D-15-02）。
  * **ブログ単位**：ブログ別の定義（例：`blogs/si-note/profile.md`）で、そのブログの全記事について対象外とする項目。
  * **記事種類単位**：ブログ別の定義の記事種類（例：`blogs/si-note/article-types.md`）で、その記事種類について対象外とする項目。
* 記事の型（②）が決まらない記事（記事種類・細分類が未登録）は、② を対象外として換算する。
* 記事ごとに判定者が個別に「対象外」とすることはできない。対象外は、ブログ別の定義で決めたものだけとする。

* 合格ラインは **95.0点** とする。

## 6. 判定

| 点数 | 判定 |
| --- | --- |
| 95.0点以上 | 公開可（公開の条件をすべて満たす場合） |
| 90.0点以上 95.0点未満 | 公開不可（改善して再評価） |
| 90.0点未満 | 公開不可（大幅な改善が必要） |

95点とは、「競合の上位記事と比べて、検索意図・正確性・理解しやすさ・独自価値の観点で同等以上であり、一部で上回る品質」を意味する。

## 7. 指摘

○ でない項目ごとに、評価者は次の「指摘」を書く（D-47。人の評価では任意）。記事改修は、指摘を「直すべきこと」として受け取る。

| 欄 | 内容 |
| --- | --- |
| どこが | 見出しの名前か、該当する文の引用 |
| 何が足りないか | 判定の基準に照らした問題 |
| どう直すか | 満たすべき状態（直した後に ○ になる状態） |

## 8. AIの評価と人の評価

* BlogOSのAI機能による評価は参考値とする。「判定者」が「人」の項目は「要人間確認」とし、AIの点数・観点の適合度には含めない。
* AIの点数は「AIが判定できる項目だけで換算した点数」として、人が確定した点数とは区別して表示する。
* 公開の可否は、人が確定した評価で判断する（D-07-03）。

| タイミング | 目的 |
