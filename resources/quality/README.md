# BlogOS 品質基準

**最終更新日:** 2026-09-24

## 1. この基準の位置付け

この基準は、BlogOSで管理・作成・改修・評価する**ブログ記事の品質基準**である。BlogOSのソフトウェア（Laravel・DB・API等）の開発ルールではない。開発ルールは `docs/BLOGOS_DEVELOPMENT_RULES.md` で定義する。

この基準は、記事の品質に関する判断の基準である。システムの仕様を定義する設計書とは優先を比べない（`CLAUDE.md` 3-1）。

BlogOSは、実行時にこのフォルダのファイルを読み込み、記事の評価・作成・改修（BlogOSのAI機能への指示を含む）に使う。

本文中の `（D-xx-xx）` は、根拠となる決定事項（`docs/BLOGOS_DECISIONS.md`）を示す。

## 2. 構成

品質基準は、**共通基準**と**ブログ別の定義**で構成する（D-06-10）。

```
resources/quality/
├─ README.md                 本ファイル
├─ common/                   共通基準（全ブログ）
│  ├─ principles.md          基本原則・判断の優先順位・適用範囲
│  ├─ scoring.md             必須条件・採点（評価項目とキー）・判定
│  ├─ writing.md             記事の構成・文章・SEO・UX・コンテンツ・収益導線の共通基準
│  └─ ai-and-operation.md    BlogOSのAI機能の実行ルール・改修範囲・品質改善の運用
└─ blogs/
   └─ si-note/               ブログ別の定義（IT技術ブログ）
      ├─ profile.md          コンセプト・想定読者・採点項目の適用・CTA・KPI
      ├─ article-types.md    記事種類・細分類・テンプレート
      ├─ site-design.md      サイト構造・ロードマップ・内部リンク
      ├─ tech-content.md     図解・コード例・エラー解説など技術記事の基準・収益導線の詳細
      └─ html-rules.md       HTMLのルール（未作成）
```

どのブログにどの定義を適用するかは、BlogOSの `blogs.quality_profile`（フォルダ名。例：`si-note`）で指定する。

## 3. 優先関係

1. 共通基準が、すべてのブログに適用される。
2. ブログ別の定義は、共通基準を具体化・追加する。共通基準の**基本原則・必須条件・判定の仕組み**を弱めることはできない。
3. ブログ別の定義で「対象外」とした採点項目（ブログ単位・記事種類単位）は、採点から除外する（`common/scoring.md` 4章）。

## 4. バージョン

| 対象 | バージョン | 記録する場所 |
| --- | --- | --- |
| 共通基準 | 1.0.1 | `common/principles.md` の冒頭 |
| si-note | 1.0.0 | `blogs/si-note/profile.md` の冒頭 |

* 共通基準とブログ別の定義は、それぞれ独立してバージョンを管理する。
* 共通基準の全ファイル（`common/` 内）は、常に同じバージョンにそろえる。1つのファイルだけを変更した場合も、全ファイルの冒頭のバージョンを更新する。ブログ別の定義のフォルダ内のファイルも同様とする（D-15-11）。
* 評価結果・AI実行記録には、評価・実行に使ったバージョンを記録する（D-06-09）。
* 採点項目のキー・配点・必須条件を変えた場合は、マイナーバージョン以上を上げる。文言だけの修正はパッチバージョンを上げる。
* 変更した場合は、各ファイルの変更履歴と `docs/BLOGOS_DECISIONS.md` に記録する。
