# si-note：技術記事の基準と収益導線の詳細

**si-note バージョン:** 1.0.0
**最終更新日:** 2026-09-24

---

## 1. 図解・表の掲載基準

次に該当する場合は、図解または表を原則として必須とする。

| 内容 | 推奨する形式 |
| --- | --- |
| 処理の流れ・実行順序 | フロー図 |
| 画面遷移・処理の遷移 | 画面遷移図・フロー図 |
| 通信処理（HTTP・APIなど） | シーケンス図・通信図 |
| データ構造・オブジェクト構造 | 構造図・ER図・概念図 |
| クラス・オブジェクト・ライフサイクル | 関係図・概念図 |
| 複数項目の比較 | 比較表 |
| 文章だけでは理解しづらい内容 | 図解・イラスト・表 |

## 2. コード例・画面例

### 2-1. 掲載が原則必須の記事

| 記事の内容 | 掲載する内容 |
| --- | --- |
| API・ライブラリの使い方 | 実行できるコード例 |
| JavaScript・HTML・CSS等の技術の解説 | コード例 |
| 設定・環境構築 | 設定画面・設定手順の画像 |
| エラーの解説 | エラーを再現するコード・原因・修正後のコード |
| 比較 | 比較表・比較のコード（必要に応じて） |

### 2-2. コード例のルール

* 「動くコード」を載せる。動作を確認していないコードは載せない。
* 再現に必要な部分は省略しない。再現に関係のない部分は載せない（D-06-06）。
* コードと一緒に、実行結果・コードの解説・注意点を載せる。
* 初心者向けの記事では、必要に応じてコード内にコメントを付ける。
* 理由の分からないサンプルを載せない。

## 3. エラー解説

初心者はエラーで検索することが多いため、エラー解説はこのブログの重要なコンテンツとする。

### 3-1. 構成

1. エラーの内容（エラー全文）
2. 発生の原因（複数ある場合はすべて示す）
3. 解決方法
4. 実際の修正例（修正前・修正後の比較）
5. 修正後の結果
6. よくある原因
7. 再発の防止策

### 3-2. 禁止事項

解決方法だけを書く、原因を説明しない、動作を確認しない。

## 4. 環境・バージョンの違いとベストプラクティス

### 4-1. 環境の違い

ブラウザ・OS・バージョン・ライブラリ・実行環境によって動作・サポート状況・注意事項が異なる場合は、必ず説明する。一部の環境だけを前提に書かない。

### 4-2. ベストプラクティス

「動けばよいコード」ではなく、「実務でも推奨される書き方」を紹介する。推奨する実装と推奨しない実装の比較、保守性・可読性・性能・セキュリティへの配慮を、必要に応じて説明する。

紹介する際は、理由・メリット・デメリット・適用する場面まで説明する。「これが一般的です」とだけ書く、根拠なく特定の方法を推奨することはしない。

## 5. 収益導線の詳細

共通基準 `writing.md` 7章を前提とする。

### 5-1. CTAの種類

書籍の紹介、Udemy講座、プログラミングスクール、比較記事、関連記事、ロードマップ、お問い合わせ。

### 5-2. 書籍

* 記事の内容を補う教材として、さらに深く学びたい読者のために紹介する。
* 紹介する場面：基礎から体系的に学びたい、実務レベルまで学びたい、資格の取得を目指す、記事では説明しきれない内容がある。
* 対象の読者、学べる内容、メリット、注意点、記事との違いを書く。
* 商品リンクだけを載せない。読んでいない書籍・記事と関係のない書籍を推奨しない。

### 5-3. Udemy講座

* 動画で学びたい読者向けに、記事で理解した内容をさらに体系的・実践的に学ぶための補助教材として紹介する。
* 紹介する場面：ハンズオン形式で学びたい、実際の開発を見ながら学びたい、初心者向けに体系的に学びたい。
* 対象のレベル、学習内容、書籍との違い、おすすめする理由を説明する。
* 関連性の低い講座を紹介しない。セールだけを訴求しない。内容を確認せずに紹介しない。

### 5-4. プログラミングスクール

* 独学が難しい読者のための選択肢として紹介する。全員には勧めない。
* 紹介の対象：独学で挫折している、転職を目指している、短期間で学習したい、メンターのサポートが必要。
* 向いている人・向いていない人、メリット・デメリット、費用の目安、学習期間を説明する。
* デメリットを書かない、根拠なく「おすすめ」と書くことはしない。

### 5-5. 比較記事

* 「どれが良いか」を決めつけるのではなく、読者に合った選択肢を示す。
* 比較表、メリット、デメリット、向いている人、向いていない人、比較の基準、結論を載せる。
* 公平で客観的に比較し、比較の基準と判断の理由を示す。「一番おすすめ」だけを書かない。
