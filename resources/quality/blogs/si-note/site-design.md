# si-note：サイト設計・ロードマップ・内部リンク

**si-note バージョン:** 1.0.0
**最終更新日:** 2026-09-24

記事を量産するのではなく、ロードマップを中心に記事同士を連携させ、学習体験を設計することを最も重要な目的とする。すべての記事は、サイト全体の中でどの役割を担うかを明確にして作成する。

---

## 1. 基本原則

1. 記事は単独で存在しない。必ず、親の記事・子の記事・関連記事・比較記事・収益記事のいずれかとの関係を持たせる。
2. 検索順位ではなく読者体験を最優先に設計する。SEOは結果であり、目的ではない。
3. 読者を迷わせない。次に読む記事が自然に分かる構造にする。
4. どの記事から訪問しても、ロードマップへ戻れるようにする。

## 2. サイトの構造

親ロードマップ（カテゴリロードマップ）
├── 子ロードマップ
│     ├── 集客記事（Know・Do・Solve・Compare・実践）
│     └── …
└── 収益記事

* 記事は必ずこの構造のどこかに所属する。孤立記事は禁止する（必須条件 `req.not_orphan`）。
* BlogOSでは、所属と関係を `article_relations`（人が登録する関係）で管理し、実際のリンクを `internal_links`（本文から抽出）で確認する。

### 2-1. 関係の種類（`article_relations.relation_type`）のsi-noteでの意味

| 値 | si-noteでの意味 |
| --- | --- |
| `parent` | 所属するロードマップ（集客記事・収益記事 → 子ロードマップ／親ロードマップ、子ロードマップ → 親ロードマップ） |
| `child` | ロードマップが束ねる記事（親ロードマップ → 子ロードマップ、子ロードマップ → 集客記事） |
| `previous` / `next` | 学習順の前の記事・次の記事 |
| `related` | 関連記事・理解に必要な記事・用語解説 |
| `advanced` | 発展・応用の記事 |
| `comparison` | 比較記事 |
| `troubleshooting` | エラー記事 |
| `monetization` | 収益記事 |

## 3. ロードマップ

ロードマップはこのブログ最大の資産である。役割は、全体像を示す、学習順序を示す、各記事へ誘導する、学習の進み具合を管理できる、カテゴリのハブになる、ことである。

ロードマップには、最低限、学習ステップ・各記事・難易度・学習時間の目安・優先度を載せる。

## 4. カテゴリ

* カテゴリは、一つの学習テーマだけを扱う。肥大化した場合は子カテゴリに分割する。
* カテゴリ内では、初学者が迷わない順番で記事を並べる。

## 5. 内部リンク

内部リンクは、SEOのためではなく、読者を次の最適な記事へ案内するために置く。

### 5-1. 最低限設置するリンク

| 種類 | 内容 |
| --- | --- |
| 上位の記事 | カテゴリのトップ（ロードマップ） |
| 学習順 | 前の記事・次の記事 |
| 関連知識 | 理解に必要な関連記事 |
| 発展学習 | 応用の記事 |
| 比較記事 | 似た概念との違い |
| エラー記事 | よく遭遇する問題 |
| 収益記事 | 必要な場合だけ |

### 5-2. 優先順位

ロードマップ → 学習順 → 理解に必要な記事 → 関連記事 → 比較記事 → エラー記事 → 収益記事

収益導線より学習導線を優先する。

### 5-3. 記事の最後に示す選択肢

記事を読み終えた読者には、必ず次の選択肢を示す。優先順位は、次の記事 → ロードマップへ戻る → 関連記事 → 比較記事 → 収益記事 とする。「記事を読み終える＝サイトから離れる」にならない構造にする。

### 5-4. 記事種類ごとの必須の導線

| 記事種類 | 必須の導線 |
| --- | --- |
| 共通 | 親ロードマップ、子ロードマップ、関連記事、用語解説記事 |
| 集客記事 | 次に読む記事、発展記事、エラー解説記事、必要に応じて収益記事 |
| 収益記事 | 比較記事、学習記事、ロードマップ |

## 6. パンくずリスト

すべての記事にパンくずリストを置き、現在地を明確にする。

例：ホーム ＞ JavaScript ＞ DOM ＞ querySelector

## 7. 孤立記事の禁止

次の記事は禁止する。公開前に必ず確認する。

* どこからもリンクされていない
* ロードマップに載っていない
* 関連記事がない
* 学習の導線がない

## 8. 公開前のサイト設計チェック

□ ロードマップに載せたか
□ 親の記事からリンクされているか
□ 子の記事へリンクしたか
□ 前後の記事を設定したか
□ 関連記事を置いたか
□ FAQ・エラー記事・比較記事へ誘導したか
□ 収益記事への導線は適切か
□ パンくずリストを置いたか
□ 孤立記事ではないか
□ 学習の導線が自然で、読者が迷わない構造か

BlogOSでは、`article_relations` と `internal_links` を比べて、これらの一部を自動で確認する。

## 9. 記事の作成・改修前に確認すること

1. 記事種類を判定する（`article-types.md`）
2. 対応するテンプレートを適用する
3. 所属するロードマップ・カテゴリを特定する
4. 必要な内部リンク（前後の記事、関連記事、FAQ、比較、エラー、収益記事）を設計する
5. テンプレートの必須要素がすべて含まれていることを確認する
6. 公開後に孤立記事にならないことを確認する
