# si-note：HTMLのルール

**si-note バージョン:** 1.1.0
**最終更新日:** 2026-09-28

**状態：作成中（案）**（D-06-07・D-33）。投稿（WordPress ID：24「JavaScriptとは？」）、親ロードマップ（固定ページ 2204）、子ロードマップ（固定ページ 2063）の HTML を基にした案である。集客記事・ロードマップの部品は決定済み。収益記事と、集客記事の細分類（比較・エラーなど）に固有の部品を加えてから、共通基準と si-note のバージョンを上げて確定する。確定するまでは、AI実行の指示文には含めない。

本ファイルは、BlogOSのAI機能（記事改修・新規記事作成・HTML出力）が書く記事本文の HTML の書き方を定める。見た目は、テーマ（子テーマ Theme-SI-Note の `style.css`、親テーマ Theme-SI-Original）の class で付ける。

---

## 1. 基本

* 本文は、WordPress のクラシックエディタ（HTML）で書く形とする。ブロックエディタのコメント（`<!-- wp:... -->`）は書かない。
* 見出しタグ・リストタグ・表のタグを、意味に合わせて正しく使う。見た目のために見出しやリストを使わない。
* `strong` は、強調する箇所だけに使う。1つの段落で多用しない。
* `style` 属性、装飾だけを目的とした `span`・`div`、本ファイルにない class を書かない。
* 余白を作るための `<br>`・空の段落を書かない。
* 文章は `<p>` で囲む。テーマは自動整形（wpautop）を行うが、BlogOSが書く本文では `<p>` を省略しない。
* 部品（本ファイル3章の枠）の前後には、人が編集しやすいよう、区切りのコメントを書く。
  ```html
  <!-- ▼▼ まとめ ▼▼ -->
  …
  <!-- ▲▲ まとめここまで ▲▲ -->
  ```

### 1-1. 見出し

* 本文の見出しは `h2` から始め、その下を `h3`、さらに下を `h4` とする。`h1` は書かない（記事タイトルはテーマが出す）。
* 部品の枠の中の見出しは、枠の見出しを `h2`、その中の小見出しを `h3` とする（投稿24の形）。
* テーマの `parts/`（教材のショートコードの枠）は枠の見出しが `h3` だが、使わなくなるため（3-10）、本文の形（`h2`）にそろえる。
* 例外：親ロードマップで学習のステップ（`h3`）の間に置く教材の枠は、枠の見出しを `h3`、その中を `h4` とする（3-15）。

## 2. 記事の全体の並び

記事種類ごとの構成（`article-types.md`）を、次の HTML の並びで書く。集客記事の例である。

| 順 | 内容 | 書き方 |
| --- | --- | --- |
| 1 | 広告を含むことの表示（教材がある記事だけ。BlogOS が入れる） | 3-1 |
| 2 | この記事で分かること | 3-2 |
| 3 | 導入文 | `<p>` |
| 4 | 広告 `[quads id=1]`（BlogOS が入れる） | 4章 |
| 5 | 本文（結論・理由・解説・コード例・実行結果・注意点）。途中に広告 `[quads id=2]`・`[quads id=4]`（BlogOS が入れる） | `h2`〜`h4`、3-3〜3-9、4章 |
| 6 | 教材の紹介（収益導線。必要な場合だけ） | 3-10 |
| 7 | FAQ | 3-11 |
| 8 | 広告 `[quads id=3]`（BlogOS が入れる） | 4章 |
| 9 | まとめ | 3-12 |
| 10 | 次に読む記事 | 3-13 |
| 11 | 関連記事 | 3-13 |

* 教材の紹介は FAQ の前に置き、FAQ とまとめの間を広告の位置とする。教材の紹介と広告を連続させないため（`article-types.md` 4-3・4-4。D-33）。

### 2-3. 集客記事の細分類ごとの本文

2章の表の「5 本文」の中身を、細分類（`article-types.md` 1-1）ごとに次の型で書く。本文より前（この記事で分かること・導入文）と、本文より後（教材の紹介・FAQ・まとめ・次に読む記事・関連記事）は、どの細分類も同じとする。

**Know記事・Do記事**（投稿24の形）：結論 → 仕組み・理由 → 手順・解説 → コード例 → 実行結果 → 注意点。

**Compare記事（比較記事）**（投稿 2744「setTimeoutとsetIntervalの違い」を基にした案）：

1. 結論（どう使い分けるか）を、ポイントの枠（3-5 `graybox`）で最初に示す。
2. 比較表（3-14）。1列目を比較の項目、2列目以降を比べる対象とする。
3. 比べる対象ごとの解説（対象ごとに `h2`。コード例・実行結果）。
4. 使い分けの判断基準（「〇〇したいなら A、△△したいなら B」）。
5. 実例（両方を使うコードなど。必要な場合）。

* 投稿 2744 は、比較表が対象ごとの解説の後にある。比較記事は、結論と比較表を先に置く（`common/writing.md` の結論を先に書く）。

**Solve記事（エラー記事）**（投稿 1485「S3でよくあるエラー」と `tech-content.md` 3-1 を基にした案）：エラーごとに次の形で書く。1つの記事で複数のエラーを扱う場合は、エラーごとに繰り返す。

```html
<h2>AccessDenied（アクセス拒否）</h2>
<p>（どんな操作をしたときに出るか）</p>
<div class="code-block">
  <pre><code class="language-text">（エラーメッセージの全文）</code></pre>
</div>

<h3>原因</h3>
<p>…（原因が複数ある場合は、リストですべて示す）</p>

<h3>解決方法</h3>
<p><strong>修正前：</strong></p>
<div class="code-block">
  <pre><code class="language-js">…</code></pre>
</div>
<p><strong>修正後：</strong></p>
<div class="code-block">
  <pre><code class="language-js">…</code></pre>
</div>
<p><strong>実行結果：</strong></p>
（3-8）

<h3>再発を防ぐには</h3>
<p>…</p>
```

* エラーメッセージは、画面の表示と同じ文を `language-text` で載せる（読者がエラーの文で検索して来るため）。
* 修正は、修正前と修正後のコードを並べる。設定画面の操作が解決方法の場合は、スクリーンショット（3-9）にする。
* 投稿 1485 は、エラーメッセージ・修正前後のコードがなく、この型に合わない（改修で直す）。

**実践記事**（投稿 2754「setIntervalでアニメーションを作る」を基にした案）：

1. 完成形（何ができるか。画面の結果はスクリーンショット）を最初に示す。
2. 作り方の手順（手順ごとに `h2`。HTML と JavaScript が分かれる場合は、`h3` の「HTML」「JavaScript」の下にそれぞれのコードの枠を置く）。
3. 完成したコードの全体（1つにまとめて、コピーして動かせる形）。
4. 応用・カスタマイズ（速度を変える、など）。

* 本文の途中に関連記事の枠（`related-box`）を置かない。本文の途中で別の記事を案内する場合は、文中のリンク（`[[記事:ID]]`）にする（投稿 1499 は、比較表の直後に関連記事の枠がある）。

### 2-4. 収益記事

si-note には、まだ収益記事がない。品質基準（`article-types.md` 5章）の構成を基にした案である。

| 順 | 内容 | 書き方 |
| --- | --- | --- |
| 1 | 広告を含むことの表示（BlogOS が入れる） | 3-1 |
| 2 | この記事で分かること | 3-2 |
| 3 | 導入文（読者の悩み） | `<p>` |
| 4 | 広告 `[quads id=1]`（BlogOS が入れる） | 4章 |
| 5 | 結論（どんな人に、どれが合うか）と、比べた基準 | ポイントの枠（3-5） |
| 6 | 比較表（紹介するすべての教材） | 3-14 |
| 7 | 教材ごとの解説（教材ごとに `h2`：概要・メリット・デメリット・向いている人・向いていない人・リンク）。途中に広告 `[quads id=2]`・`[quads id=4]` | 2-4 の下の例 |
| 8 | 選び方（判断の基準・目的別のおすすめ） | `h2` |
| 9 | FAQ | 3-11 |
| 10 | 広告 `[quads id=3]`（BlogOS が入れる） | 4章 |
| 11 | まとめ（結論をもう一度） | 3-12 |
| 12 | 次に読む記事・関連記事 | 3-13 |

教材ごとの解説：

```html
<h2>いちばんやさしいJavaScriptの教本 第2版 <span class="pr-label">PR</span></h2>
<p>（概要。公開されている情報に基づく）</p>
<h3>メリット</h3>
<ul><li>…</li></ul>
<h3>デメリット・注意点</h3>
<ul><li>…</li></ul>
<h3>向いている人・向いていない人</h3>
<ul><li>向いている人：…</li><li>向いていない人：…</li></ul>
[[教材:ID]]
```

* 収益記事では、教材の紹介の枠（3-10 の `book-box` など）を使わず、教材の解説が本文そのものになる。リンク（`[[教材:ID]]`）は、教材ごとの解説の最後に置く。
* 比較表の教材名は、その教材の解説（`h2`）へのページ内リンクにする。ページ内リンク用の `id` は、AI が書かず、BlogOS が付ける（名前の付け方をそろえるため）。
* 比較の対象でない種類の教材（例：書籍の比較記事でのスクール）は、集客記事と同じ教材の枠（3-10）で、FAQ の前に置く。

## 3. 部品

### 3-1. 広告を含むことの表示（ステマ規制。`common/writing.md` 7-4）

教材（アフィリエイトのリンク）を紹介する記事では、読者が教材のリンクを見る前に広告を含むと分かるよう、記事の冒頭（「この記事で分かること」の前）に次の1行を置く。

```html
<p class="pr-note">本記事にはプロモーション（アフィリエイト広告）を含みます。</p>
```

* AI は書かない。BlogOS が、教材の目印がある記事にだけ入れる（書き忘れ・文言の揺れを防ぐため）。教材がない記事には入れない。
* 文言は「広告」「プロモーション」「PR」など、広告と分かる言葉にする。末尾だけ・小さい文字・背景に紛れる色での表示は不十分とされている（消費者庁のステルスマーケティングの運用基準・Q&A）。
* AdSense の広告は、Google が「広告」「スポンサーリンク」の表示を付けるため、この表示の対象にしない。
* 教材の枠の見出しにも「PR」の印を付ける（3-10）。記事の「おすすめ」と区別するため。
* 【テーマの作業】子テーマに `pr-note`（本文と同じ大きさの文字、枠付き）と `pr-label`（3-10）の見た目を加える。

### 3-2. この記事で分かること

```html
<div class="point-box">
  <h2>この記事で分かること</h2>
  <ul>
    <li><strong>特に重要な項目</strong></li>
    <li>項目</li>
  </ul>
</div>
```

* 4〜6項目。記事の見出しの内容と一致させる（本文にない内容を書かない）。
* 検索意図の中心になる項目だけ `strong` にする（2〜3項目まで）。

### 3-3. 段落・強調

* 1つの `<p>` は、1つの話題（2〜4文程度）とする。
* 「一言で言うと」「結論」にあたる文は `strong` にする。

### 3-4. 用語の補足

初心者がつまずく用語は、その用語が初めて出た箇所の直後に、補足の枠で説明する。

```html
<div class="supplement-box">
  <strong>補足：DOMとは？</strong><br>
  Webページの構造をツリー状に表現したもの。JavaScriptからページ内容を変更できる仕組み。
</div>
```

* 1つの枠で、1つの用語だけを説明する（投稿24には、1つの枠に2つの用語を入れた箇所がある）。
* リストの項目の補足は、`<li>` の中（項目の文の後）に置く。
* 説明は1〜2文とする。詳しい説明が必要な用語は、用語解説の記事へ内部リンクする。

### 3-5. ポイント

読者に覚えてほしい結論・推奨は、グレーの枠で示す（親テーマの `graybox`。既存の記事で使っている）。

```html
<div class="graybox">
  <strong>初心者は <code class="inline-code">defer</code> を使うのがおすすめ</strong><br>
  理由：複数ファイルを読み込んでも順番が崩れないため
</div>
```

### 3-6. 注意・よくあるエラー

読者が誤解しやすい点・よくある失敗・エラーになる書き方は、注意の枠で示す。注意点は、読者が誤解する前に、本文の該当する箇所に置く（`common/writing.md` 3-6。記事の末尾だけにまとめない）。

```html
<div class="caution-box">
  <strong>注意：</strong><code class="inline-code">defer</code> は、外部ファイル（<code class="inline-code">src</code> 属性がある <code class="inline-code">script</code>）にだけ効きます。
</div>
```

* 1つの枠に、1つの注意点を書く（1〜3文）。
* 親テーマの `redbox`・`yellowbox`（STINGER の装飾）は使わない。
* 【テーマの作業】子テーマに `caution-box`（黄色の背景と左の線）の見た目を加える。

### 3-7. コード

コードブロック：

```html
<div class="code-block">
  <pre><code class="language-html">&lt;button onclick="showMessage()"&gt;クリック&lt;/button&gt;

&lt;script&gt;
function showMessage() {
  alert("こんにちは！JavaScriptが動きました！");
}
&lt;/script&gt;</code></pre>
</div>
```

* `pre` と `code` で囲み、`code` に、そのコードの言語の class（Prism。`language-` + 言語名）を付ける。言語は記事の内容（カテゴリ）で決まる。例：`language-html`・`language-css`・`language-js`・`language-java`・`language-python`・`language-sql`・`language-bash`・`language-json`。実行結果・コマンドの出力など、言語でないものは `language-text` とする。
* 【テーマの作業】テーマが読み込む Prism（`prism.min.js`）は、HTML・CSS・JavaScript 系だけに色を付ける。Java・Python などにも色が付くよう、子テーマで Prism の autoloader（使っている言語のファイルを自動で読み込む）を加える。
* `<`・`>`・`&` は、`&lt;`・`&gt;`・`&amp;` にする。
* `<code>` の直後と `</code>` の直前に、改行・空白を入れない（コードの前後に空行が表示されるため。投稿24にはある）。
* コードの前に「何をするコードか」、後に「実行結果」と「解説」を書く（`tech-content.md` 2-2）。

文中のコード（関数名・タグ名・属性名など）：

```html
<code class="inline-code">script</code>
```

### 3-8. 実行結果

コードの直後に、実行結果を書く（`tech-content.md` 2-2）。

```html
<p><strong>実行結果：</strong></p>
<div class="code-block">
  <pre><code class="language-text">こんにちは！JavaScriptが動きました！</code></pre>
</div>
```

* コンソールの出力・コマンドの結果など、文字の結果は、コードの枠と同じ形で `language-text` にする。
* 画面の表示（ボタン・ダイアログ・レイアウトなど）が結果の場合は、スクリーンショット（3-9）にする。

### 3-9. 画像

```html
<p><img src="…" alt="HTML・CSS・JavaScriptの役割図（骨格・見た目・動き）"></p>
```

* `alt` には、画像の内容が分かる説明を書く（「画像」「図」だけにしない）。
* AI は画像の HTML を書かず、BlogOS に登録した画像の目印（`[[画像:ID]]`）を書く。BlogOS が WordPress のメディアの `img` に置き換える（D-32。記事への組み込みは本ファイルの確定後に作る）。
* 画像は、WordPress のメディアライブラリに登録したものを使う。どの記事でどの画像を使っているかは、BlogOS で管理する。既存の記事の `/wp-content/img/…` の画像は、記事を改修するときにメディアライブラリの画像に置き換える。
* キャプション（`figure`・`figcaption`）は使わない。画像の説明は、画像の前後の本文と `alt` に書く。

### 3-10. 教材の紹介（書籍・Udemy・スクール）

* 教材は、BlogOSに登録した教材だけを紹介する（`tech-content.md` 5-6）。AI は教材の HTML・リンクを書かず、目印（`[[教材:ID]]`）と、記事に合わせた紹介文を書く。BlogOS がリンクの HTML に置き換える（D-30-06）。
* 枠は種類ごとに分け、書籍 → Udemy → 問題集 → スクールの順に並べる。枠と枠の間に広告を置かない。
* 枠の見出し（`h2`）の最後に、PR の印 `<span class="pr-label">PR</span>` を付ける（3-1）。BlogOS が付ける。
* 枠の見出し（`h2`）の下に、その学び方が向いている人・理由を書き、教材ごとに `h3`（教材名）・説明・「この本（講座・スクール）で解決できること」のリスト・リンクを置く。

書籍：

```html
<div class="book-box">
  <h2>JavaScript 初心者におすすめの学習書籍 <span class="pr-label">PR</span></h2>
  <h3>書籍で学ぶのが向いている人</h3>
  <ul>
    <li>…</li>
  </ul>
  <p>…</p>

  <h3>いちばんやさしいJavaScriptの教本 第2版</h3>
  <p>…（公開されている情報に基づく説明）</p>
  <p><strong>この本で解決できること：</strong></p>
  <ul>
    <li>…</li>
  </ul>
  <p><strong>注意点：</strong>…（例：発行が古く、最新の書き方は載っていない）</p>
  <div class="book-links">
    <a href="（Amazonのリンク）" rel="nofollow sponsored" class="amazon-btn">Amazonで見る</a>
    <a href="（楽天のリンク）" rel="nofollow sponsored" class="rakuten-btn">楽天で見る</a>
  </div>
</div>
```

Udemy：

```html
<div class="udemy-box">
```

### 3-11. FAQ

```html
<div class="faq-box">
  <h2>よくある質問（FAQ）</h2>

  <div class="faq-item">
    <div class="faq-q">
      <span class="faq-label">Q1</span>
      <p>JavaScriptは独学で習得できますか？</p>
    </div>
    <div class="faq-a">
      <span class="faq-label-a">A</span>
      <p>独学でも習得は可能です。…</p>
    </div>
  </div>
</div>
```

* 質問の番号は Q1 から順に付ける。数は記事種類の目安に従う（`article-types.md`）。
* 回答は、結論を1文目に書き、2〜4文でまとめる。
* FAQ の構造化データ（`<script type="application/ld+json">`）は書かない。Google は 2023年から、FAQ のリッチリザルト（検索結果での表示）を政府・医療の権威あるサイトだけに限っているため。既存の記事の構造化データは、記事を改修するときに削除する。

### 3-13. 次に読む記事・関連記事

```html
<div class="next-article-box">

  <ul>
    <li>
      <p class="reason">（この記事を読んだ後に、なぜこの記事を読むとよいか）</p>

    </li>
  </ul>
</div>

<div class="related-box">
  <h2>関連記事</h2>
  <ul>
    <li>
      <p class="reason">（この記事との関係）</p>
      → <a href="/js/js-basic/39.html">（記事タイトル）</a>
    </li>
  </ul>
</div>
```

* AI は、記事へのリンクの HTML を書かず、記事の目印（`[[記事:ID]]`。5章）を書く。BlogOS が、その記事の今の URL（サイト内の相対パス）とタイトルのリンクに置き換える。リンクの文字が古いタイトルのまま残らないようにするため（固定ページ 2063 に、投稿24の古いタイトルのリンクが残っていた）。
* 次に読む記事は1件（多くても2件）、関連記事は2〜4件とする。
* リンク先は、BlogOSが同期している公開済みの記事だけとする（存在しない記事へリンクしない）。
* 子ロードマップの「次のステップ」「全体ロードマップ」も、同じ形（`<ul><li>` の中に `reason` とリンク）で書く。
* 【テーマの作業】子テーマに `reason` の見た目（少し小さい灰色の文字）を加える。

### 3-15. ロードマップの学習のステップ

親ロードマップ（ステップごとに子ロードマップへ案内する）：

```html
<div class="roadmap-category">
  <h3>ステップ1：JavaScriptの基礎を固める</h3>
  <p>（このステップで学ぶこと・なぜこの順番か）</p>
  <ul>
    <li>[[記事:ID]]</li>
  </ul>
</div>
```

子ロードマップ（ステップごとに記事へ案内する）：

```html
<div class="roadmap-step">
  <h3>ステップ1：JavaScript の導入・基本書式（超入門）</h3>
  <p>（このステップで学ぶこと）</p>
  <ul>
    <li>[[記事:ID]]</li>
  </ul>
</div>
```

* ステップの見出しは `h3`、「ステップN：」から始める。ステップの並びは、学習の順番とする。
* ステップの枠（`roadmap-category`・`roadmap-step`）は、ステップだけに使う（記事一覧への導線などには使わない）。
* 子ロードマップに載せる記事は、そのカテゴリの公開済みの記事をすべて、いずれかのステップに入れる（載っていない記事は、孤立記事の原因になる）。
* 親ロードマップの教材の枠は、関係するステップの直後に置き、ステップの見出しに合わせて枠の見出しを `h3`、中を `h4` とする。class は `roadmap-book-box`・`roadmap-udemy-box`・`roadmap-school-box` とする（中の書き方は 3-10 と同じ）。子ロードマップの教材の枠は、集客記事と同じ（3-10）。

## 4. 広告（AdSense）

広告は、プラグイン（WP QUADS）に登録した AdSense の広告ユニットを、ショートコード `[quads id=N]` で置く（既存の154記事で使っている）。

| ショートコード | AdSense の広告ユニット | 置く位置 |
| --- | --- | --- |
| `[quads id=1]` | rectangle-top | 導入文の直後 |
| `[quads id=2]` | rectangle-middle | 記事中（H2 の間） |
| `[quads id=4]` | rectangle-middle2 | 記事中の2つ目（記事の分量が多い場合だけ） |
| `[quads id=3]` | rectangle-bottom | まとめの直前 |

* AI は広告のショートコードを書かない。BlogOS が、記事の本文から決まった位置を探して入れる（D-33）。
  * id=1：導入文の後（最初の `h2` の前）。
  * id=2：本文の中ほどの `h2` の前。
  * id=4：本文が長い記事（タグを除いた本文が 6,000字以上で、`h2` が6個以上）だけ、id=2 と離れた `h2` の前。
  * id=3：FAQ の後、まとめの前。
* 教材の枠の直前・直後、教材の枠と枠の間、この記事で分かることの前には置かない（`common/writing.md` 7-1「CTA と広告を連続させない」）。
* 既存の記事の広告のショートコードは、記事を改修するときに BlogOS が入れ直す。

## 5. BlogOS の目印

AI が本文に書く目印と、BlogOS が置き換える HTML は、次のとおりとする（本ファイルの確定後に作る）。

| 目印 | 置き換える内容 |
| --- | --- |
| `[[教材:ID]]` | 登録した教材の紹介（3-10 のリンクの部分） |
| `[[画像:ID]]` | 登録した画像の `img`（WordPress のメディア） |
| `[[記事:ID]]` | 記事（投稿・固定ページ）の今の URL とタイトルのリンク |

AI が書かず、BlogOS が入れるもの：広告を含むことの表示（3-1）、教材の枠の PR の印（3-10）、広告のショートコード（4章）。
