# 守ること

* 「今ある記事」「作業中の新しい記事」と同じ内容・同じ検索意図の案は出さないでください（重複した記事は、検索でも読者にも不利です）。
* 1つの案は、1つの検索意図（読者の1つの疑問・目的）にしてください。
* 品質基準のサイト構造（site-design.md）に沿って、ロードマップの学習の順番の中での位置を考えてください。前提の知識が足りない案は、その前提の記事の案も出してください。
* 「検索語句」は、読者が実際に検索した語句です。順位が低い・今の記事の内容と合っていない語句は、新しい記事の候補になります。
* 子カテゴリの記事の案は、10件前後（多くても15件）にしてください。子カテゴリの案は、3〜8件にし、それぞれ最初に書く記事の案を5〜10件付けてください。
* 優先度（priority）は、読者の必要性（学習の順番で先に必要か・よく検索されるか）で決めてください。

# 出力の形式

次のJSONだけを、```json のコードブロックで出力してください。「子カテゴリの、まだ記事にしていない内容」を企画するときは articles だけを、「親カテゴリの、足りない子カテゴリ」を企画するときは categories だけを書き、もう一方は [] にしてください。

```json
{
  "summary": "企画の全体の考え方（2〜4文）",
  "articles": [
    {
      "title": "タイトル案（品質基準のタイトルの型に沿う）",
      "main_keyword": "メインキーワード（空白で区切った語）",
      "sub_keywords": ["サブキーワード"],
      "search_intent": "読者の疑問・目的（1〜2文）",
      "article_type": "記事種類の値（下の選べる値）",
      "article_subtype": "細分類の値（集客記事のとき。または null）",
      "roadmap_step": "ロードマップのどのステップに入るか（新しいステップなら、その名前）",
      "priority": "high / medium / low",
      "reason": "この記事が必要な理由（検索語句・学習の順番の抜け・公式の資料との比較など）",
      "sources": ["根拠の URL"]
    }
  ],
  "categories": [
    {
      "name": "子カテゴリの名前（例：Array（配列操作））",
      "slug": "スラッグ（英小文字・数字・ハイフン。例：js-array）",
      "scope": "このカテゴリで扱う範囲（1〜2文）",
      "position": "学習の順番の中の位置（どのカテゴリの後か）",
      "priority": "high / medium / low",
      "reason": "このカテゴリが必要な理由",
      "sources": ["根拠の URL"],
      "first_articles": [ （articles と同じ形の、最初に書く記事の案） ]
    }
  ]
}
```
