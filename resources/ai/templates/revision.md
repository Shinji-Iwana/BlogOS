# 守ること

* 改修範囲を超えて変更しないでください。どの改修範囲でも、誤った情報は必ず修正してください。
* 根拠を確認できない情報を推測で書かないでください。確認が必要な箇所は、最後の「確認が必要な点」に書いてください。
* 「実際に試した」「実務で使っている」など、あなたが経験していないことを事実として書かないでください。実体験・検証の内容は、下の「人が提供した情報」にあるものだけを使ってください。
* 本文は、品質基準の「HTMLのルール」（html-rules.md）に従った HTML で、省略せずに全文を出力してください。ブロックエディターのコメント（`<!-- wp:paragraph -->` 等）は書かないでください。
* 部品は、html-rules.md の書き方（class）どおりに書いてください。記事種類の並び（html-rules.md 2章・2-1・2-2）に従い、特に次の枠を省略しないでください：冒頭の `point-box`（ロードマップは「このページの使い方」）、FAQ の `faq-box`（`faq-item`・`faq-q`・`faq-a`）、まとめの `summary-box`、次に読む記事の `next-article-box`、関連記事の `related-box`。見出しと段落だけで書かないでください。
* タイトル・メタディスクリプションは、品質基準（writing.md 3-1・3-2、article-types.md 1-2 タイトルの型）に従ってください：タイトルは先頭28文字以内にメインキーワードと何が分かるかを入れ、全体40文字程度まで。【〈技術〉入門】はタイトルの最後に置き、先頭に【…】を置かない。メタディスクリプションは80〜120文字で、先頭50文字ほどに誰のどんな疑問を解決するかを入れる。
* 読者は、ITに触れたことがない人を基準にしてください。本文に出てくる、ITに触れたことがない人が意味を言えない用語（カタカナの用語・英字の略語・漢字の専門用語）は、改修範囲にかかわらず、すべて補足の枠（`supplement-box`）で説明してください（品質基準 profile.md 3-5、html-rules.md 3-4）。補足するのは、あなたが書いた本文に実際に出てくる用語だけです。本文に出てこない用語（関連する用語・先回りの説明）の補足は作らないでください。補足の説明文は、専門用語を別の専門用語で言い換えず、ITに触れたことがない人が分かる日常の言葉で書いてください。現在の本文で説明していない用語にも、補足を加えてください。加えた用語は「変更点」に一覧で書いてください。
* 次のものは BlogOS が入れるため、書かないでください。現在の本文にあるものは削除してかまいません：広告のショートコード（`[quads id=…]`）、広告を含むことの表示（`pr-note`）、PR の印（`pr-label`）、FAQ の構造化データ（`<script type="application/ld+json">`）。
* 内部リンクは、HTML の `<a>` を書かず、下の「記事の一覧」にある目印（例：`[[記事:24]]`）をそのまま書いてください。リンクの文字は BlogOS が記事のタイトルにします。一覧にない記事へリンクしないでください。
* 教材（書籍・Udemy・問題集・スクール）は、下の「紹介してよい教材の候補」から、品質基準（tech-content.md 5-6 の選び方と数の上限）に従って選んでください。合う教材がなければ紹介しないでください。候補の教材の情報は、BlogOS が公開されている情報（出版社・販売サイト・講座やサービスの説明）から調べ、人が確認したものです。紹介文はこの情報の範囲で書いてください（情報にないことは書かない）。「内容や現在の仕様との適合性を確認できない」ことを理由に外さないでください。外すのは、品質基準の選び方（記事の内容・向いている場面・レベル・対象のバージョンが合わない、数の上限）に当てはまる場合だけです。紹介しない場合は、理由を「変更点」に書いてください。枠（`book-box` 等）・見出し・紹介文はあなたが書き、リンクの位置には目印（例：`[[教材:3]]`）だけを書いてください。候補にない教材を紹介しないでください。テーマのショートコード（`[aws_book_box_beginner]` など）は使わず、記事に合わせた教材の紹介に置き換えてください。
* 画像は、載せる位置に目印を書いてください。下の「この記事の画像」にある画像はその目印（例：`[[画像:5]]`）を、新しく必要な画像は `[[画像:新規1]]` のような目印を書き、「=== 画像の依頼 ===」に内容を書いてください。図解（diagram）は3枚まで、イラスト（illustration）は1枚までです。操作画面・実行結果の画面は、スクリーンショット（screenshot）として依頼してください（人が撮ります）。現在の本文にある `<img>` タグは、消さずにそのまま残してください。

# 出力の形式

次の見出しの行（=== で囲んだ行）をそのまま使い、この順で出力してください。見出しの行の間に説明を入れないでください。

=== タイトル ===
（改修後のタイトル）
=== メタディスクリプション ===
（検索結果に表示される説明。品質基準の「メタディスクリプション」の基準に沿って書く）
=== 抜粋 ===
（改修後の抜粋。不要なら空）
=== 本文 ===
（改修後の本文の全文）
=== 画像の依頼 ===
（新しく必要な画像。次の形の JSON の配列。なければ []）
```json
[
  {
    "key": "新規1（本文の [[画像:新規1]] と同じ）",
    "kind": "diagram / illustration / screenshot",
    "title": "画像の名前（短く）",
    "description": "何をどう描くか（図解は、要素・流れ・関係を具体的に。スクリーンショットは、撮る画面と操作の手順）",
    "alt": "画像の代わりの文章（日本語。1〜2文）",
    "illustration_prompt": "illustration のときだけ。画像モデルへの英語の指示文（画像の中に文字を入れない）。それ以外は null"
  }
]
```
=== 変更点 ===
（何をなぜ変えたかの箇条書き）
=== 自己評価 ===
（品質基準の採点で、改修後に残っている不足点）
=== 確認が必要な点 ===
（人が確認・検証すべき箇所。なければ「なし」）
