# 1. 本書の目的と位置付け

本書は、BlogOS の画面（業務画面・確認画面・ポップアップ）の見た目と操作を揃えるための、共通のルールを定義する。

全画面の見直し（2026-11-21〜）で、画面ごとにばらばらだった部分を、利用者の指示に基づいて1つずつ決め、決めたものから本書に書き足す。決めた理由は `BLOGOS_DECISIONS.md` に記録する。

見直しが済んだら、画面ごとの画面設計書と画面遷移図を作り、BlogOS の上から見られるようにする（本書はその共通の部分になる）。

画面の種類（業務画面・API確認画面・DB確認画面）の定義は ARCHITECTURE 6-3 による。

## 1-1. 全画面に共通のルール

* 文字のないアイコン（ヘッダーのお知らせ・マイク・ログアウト、ポップアップの題名のモード・種類のアイコンなど）には、マウスを乗せるとツールチップで名前を出す（`title="名前"`）。アイコンの枠のどこに乗せても出るようにする（D-108-01）。
* BlogOS の DB にテーブルを新しく作る（または変える）ときは、他のテーブルと同じように、一覧と詳細の画面を用意（更新）し、XServer情報の DB の一覧から行けるようにする。詳細を開けるように、主キーは1列にする（D-110-01）。
* 画面に URL を出す項目は、どの画面でもリンクにし、別のタブで開く（`target="_blank" rel="noopener"`）。画面ごとに書かず、共通の `App\Support\UrlLink::html()` で出す（URL でない値は文字のまま）。入力欄の中の URL と、文章の中の URL は対象にしない（D-113-01）。
* WordPress が決めている値（記事の公開の状態・投稿タイプ・タクソノミーなど）を日本語で出すときは、WordPress が持つ日本語の名前に揃える（例：publish は「公開済み」、future は「予約済み」、trash は「ゴミ箱内」）。BlogOS の中で別の言い方をしない（D-119-01）。

# 2. 画面の上の部分

## 2-1. トップページへの戻り方

* 画面の上に「トップページに戻る」のリンクは出さない。トップページへは、全画面に共通のヘッダーの「BlogOS」から戻る（D-97-02）。
* 横から出る画面のパネル（`#screen-drawer`）で開いた画面は、パネルを閉じるとトップページに戻る。
* パネルの右上は「全画面で開く」→ 再読み込みのアイコン →「×」（閉じる）の順に並べる。再読み込みは、パネルの中の画面だけを開き直す（ブラウザの再読み込みは、トップページを開き直してパネルが消えるため。D-112-01）。

## 2-2. 戻る先のリンク

* 「〜に戻る」のリンクは、その画面を実際に開く元の画面にだけ向ける。開いた元と関係のない画面への「戻る」は出さない（D-97-03。例：取り込んだ WordPress のデータのテーブル（投稿など）の一覧の画面に「XServer情報に戻る」を出さない）。
* 同じ画面（ファイル）を複数のテーブル・種類で使う場合は、開く元が違うものごとに出し分ける。

## 2-3. 見出し（画面の名前）

* 見出しに件数を出さない（件数は、表の上の表示件数の行に出す。3-2）（D-101-01）。
* 一覧の画面の名前は「～一覧」（「～の一覧」としない。例：投稿一覧・編集案一覧・ブログ一覧）（D-101-02）。その画面へのリンクの名前も、画面の名前に合わせる。
  * 例：教材一覧・画像一覧・AI実行履歴一覧・AIまとめて実行履歴一覧・WordPress反映履歴一覧（D-102）。

## 2-4. パネルの題名

* 「英字＋日本語」の題名（例：`SYNC 同期`）にするのは、次の3つだけ（D-117-01）。
  * トップページのパネル（状態のパネルと、分野ごとのリンクのパネル。`.hud-panel-code`）
  * 右から出るパネルの「SCREEN」（`.screen-drawer-code`）
  * 共通ヘッダーのメニュー（例：`HISTORY 履歴`。`.site-menu-code`）
* それ以外の、各画面の中のパネル（`<section class="panel">` などの見出し）は、日本語だけにする（例：「条件」「レコード」「変更履歴」）。英字の札（`data-code`）は付けない。
  * ログイン画面・エラー画面のパネルも同じ。エラー画面は、エラーの番号を題名の後ろに出す（例：「ページが見つかりません（404）」）。

# 3. 表の一覧

## 3-1. ページ送り

* 表で出す一覧は、全て1ページ最大50件で、ページに分けて全件を出す。件数の上限で切らない（D-98-01）。
* 表ではなく、画像などを並べて出す一覧（画像一覧）も、同じページ送りと表示件数の行にする（D-102-05）。
* 部品は `App\Support\ListPage`。DB から読む一覧は `->paginate(ListPage::PER_PAGE)->withQueryString()`、画面のために集めた配列・コレクションは `ListPage::of($items, $pageName)`。ページ送りのリンクは、表の下に `{{ $paginator->links() }}` で出す（`partials/pagination`）。
* 1つの画面に表が複数あるときは、表ごとにページの名前（`$pageName`）を分け、`->fragment()` でページを送ったときにその表の位置に戻す。閉じた欄（`<details>`）の中の表は、ページを送ったときは開いたままにする。
* チェック・入力をしてまとめて送る表は、表示しているページの行だけを送る。保存は、送られた行だけを変える（ほかのページの行を消したり空にしたりしない）。
* 行の数が決まっていて50件に届かない表（1件の画面の項目の表、種類・区分ごとの表、設定の項目、ポップアップの中の表など）には、ページ送りの部品を付けない。

## 3-2. 表示件数の行

* ページ送りをする表の上に、表示件数の行を出す（`partials/history-count`。D-98-02）。
  * 全体が50件未満：「表示件数：○件（新しい順）」
  * 全体が50件以上：「表示件数：○件（新しい順、最大50件。全○件をページに分けて表示）」
* 括弧の中は、その表の並び順（`order` で渡す。省略時は「新しい順」）。

## 3-3. 日時のセル

* 表に出す項目が日時のときは、日付で1行・時刻で1行の2行にし、折り返さない決まった幅（一番長い行の文字数の幅）で出す。日付だけ・時刻だけも、同じように折り返さない決まった幅で出す（D-111-01）。
* 画面ごとに書かない。共通の `public/js/blogos.js` が、全画面の表（`table.data`）の、中身が日時・日付・時刻だけのセルを見つけて、この形にする（`.cell-dt`・`.dt`。見た目は `public/css/blogos.css`）。表のセルには、日時だけを入れる（「（〇〇 に変化）」のように文章と混ぜると、この形にならない）。
* カードの形（スマホなどで表が収まらないとき）でも、日時は2行で出す。
* 2行にするのは、一覧の表（列の見出しの行がある表）だけ。詳細画面の「項目名と値」の表（列の見出しの行がない表）は、日時を1行で出す。日付・時刻の途中では折らず、幅が足りないときだけ、日付と時刻の間で折れる（D-111-02）。

## 3-4. アコーディオンの題名

* アコーディオン（押すと開く `<details>` の一覧）の題名に、複数の項目を並べるときは、「 / 」（半角スペース＋「/」＋半角スペース）でつなぐ。「・」ではつながない（D-114-01）。
  * 例：`#61 / 毎日の同期 / 成功 / 2026-11-23 03:00:04 〜 2026-11-23 03:00:16`（WordPressとの同期履歴）、`2026-09-26 02:57:45 / blogos_manual / __created`（DB確認の詳細画面の変更履歴）。
* 項目の中の「・」（メッセージの文章など）は、区切りではないため、そのまま出す。

## 3-5. ID・金額・数値などのセル

* 一覧の表（列の見出しの行がある表）に出す次の値は、折り返さずに出す（「1／9／4」「$0.／1」「13.43.／0」のように縦に折れない。D-116-01・D-116-02）。
  * ID：中身が番号だけのセル（例：`194`、編集案の `#181`）。
  * 金額：中身が金額だけのセル（例：`$0.1`、`$1,234.5678`、`¥1,234`、`＋ $0.20`、`1,234円`）。
  * 数値：中身が数値だけのセル（例：`2,801`、`0.000`）。件数は「件」が付くもの（`12件`）も付かないもの（`61`）も同じ（D-116-02）。
  * バージョン：中身がバージョンだけのセル（例：`13.43.0`、`8.4.28`、`10.6.12-MariaDB`。D-116-02）。
  * 容量：中身が容量だけのセル（例：`717.8 KB`、`3.2 MB`、`9MB`。D-116-02）。
  * 時間：中身が秒数などの時間だけのセル（例：`6.7秒`、`18ms`、`84分24秒`、`1時間2分`。D-116-02）。
* 日時（3-3）と同じく、画面ごとに書かない。共通の `public/js/blogos.js` が、全画面の一覧の表（`table.data`）の、中身が上の値だけのセル（リンクなど1つの要素で包んだものも含む）に `.cell-nowrap` を付け、折り返さない（見た目は `public/css/blogos.css`）。
* 文章の中の値（例：「1回 $0.01」「文章の入力 $5・画像の入力 $8」「12〜34秒で1周」）は、ほかの文章と同じく折り返す。
* 詳細画面の「項目名と値」の表（列の見出しの行がない表）は、対象にしない（今のまま）。

## 3-6. 表の文字の揃え方

* 一覧の表（列の見出しの行がある表）は、列の見出しを中央揃え、値を左揃えにする（D-118-01）。ただし、数値の列は右揃えにする（セルに `.cell-num` を付ける。D-118-02）。
* 「項目名と値」の2列の表（列の見出しの行がない表。詳細画面など）は、項目名も値も左揃えにする（D-118-01）。ただし、判定の基準の中の表（「○」「△」と補足）の記号は中央揃え（D-118-02）。
* 画面ごとに書かない（`style="text-align:…"` を付けない）。共通の `public/css/blogos.css` が `table.data` の揃え方（と `.cell-num`）を決める。thead のない一覧の表は、`public/js/blogos.js` が列の見出しの行に `.table-header-row` を付ける。
* カードの形（狭い画面）は、全て左揃え。

# 4. ポップアップ

## 4-1. 入力欄

* 入力欄は、ラベルを上・入力欄を下にした1組（`.modal-field`）で、縦に並べる（D-99-01）。
  ```blade
  <label class="modal-field">
      <span class="modal-label">項目の名前 @include('partials.tip', ['tip' => '…'])</span>
      <input type="text" name="…">
  </label>
  ```
* 1つの項目で選ぶ欄をいくつも使うとき（定期実行の「いつ」）は、`<div class="modal-field">` の中の `.modal-label` の下に、`<span class="modal-controls">` で1行に並べる。
* 組になる2つの欄（例：モデルと推論の深さ、改修範囲と改修の繰り返し、額と日時、教材の種類と状態）は、ポップアップの幅を左右に半分ずつ分けて並べてよい（`<div class="modal-field-row">` の中に `.modal-field` を2つ）。狭い画面（幅 560px 以下）では縦に並べる（D-104-01・D-106-01）。
* AI のモデルと推論の深さを選ぶ欄は、どこでも同じ書き方にする：モデルは料金付き（「gpt-6-luna（入力 $0.1・出力 $0.5）」）、推論の深さの none は「none（推論なし）」、モデルで選べない推論の深さは選べないようにする（D-105-01）。選択肢は `@include('partials.ai-model-options', ['models' => …, 'selected' => …])`・`@include('partials.ai-effort-options', ['selected' => …])`、選ぶ欄に `data-model="名前"`、推論の深さの欄に同じ名前の `data-effort` を付ける（選べない推論の深さは、`layouts/header` の JavaScript が選べなくする）。料金の単位（1Mトークンあたりの米ドル）は、ラベルの「?」に書く（D-105-02）。
* ラベルの後ろに「：」は付けない。
* ツールチップ（?）は、ポップアップの題名の右か、各項目のラベルの右に出す。入力欄の後ろには出さない。
* 1行の文字の入力欄は、ポップアップの幅いっぱい。入力欄に `style` で幅を書かない。
* 複数行の入力欄は `rows="3"`（3行が見える高さ）。それより長いときは、欄の中でスクロールする。
* 文字の入力欄以外（選ぶ欄・日時の欄など）は、値の全文が切れずに見える幅（ポップアップの幅は超えない）。
* チェックボックス（有効など）は「☑ 名前 ?」の1行のまま。いくつかから選ぶ形の欄（方式・テーマ）は、これまでどおり。
* ポップアップの幅は、全て 720px（狭い画面では、画面の幅から左右 20px ずつ引いた幅）。ポップアップごとに幅を書かない（D-99-02）。
* ポップアップは、スマホの画面から見切れない（幅に内側の余白を含める。画面の横のはみ出しは切る。D-99-01）。
* ラベル（`.modal-label`）は青、値（入力欄・選んだ値）は白で出す。スマホの表のカードの、列の見出し（青）と値（白）と同じ形（ironman：`var(--im-cyan)`・HUD の字体・12px）。チェック・選ぶ欄の選択肢の文字は、値なので白。ポップアップの中の「名前：値」の名前（定期実行の「次回実行：」など）は `<span class="modal-info-label">`、いくつかの欄をまとめる項目の名前は `.modal-label` で、同じく青にする。blank のテーマは色を付けない（D-109-01）。

## 4-2. モード（題名のアイコンと、送るボタンの名前）

* ポップアップは、開くときのモードを決める（D-100）。ポップアップに `data-modal-mode` を書く。

| モード | `data-modal-mode` | 題名の左のアイコン | 送るボタン |
| --- | --- | --- | --- |
| 新規 | `create` | ＋ | 登録 |
| 編集 | `edit` | 鉛筆 | 更新 |
| 切替 | `switch` | 回る矢印 | 切替 |
| 情報 | `info` | i（インフォメーション） | 出さない |
| 削除 | `delete` | ごみ箱に赤の×を重ねたもの（D-123-01） | 削除 |
| ゴミ箱へ移動 | `trash` | ふたを開けたごみ箱に、紙くずを入れるもの（D-123-01） | ゴミ箱へ移動 |

* 題名は `partials/modal-title`（アイコン・題名・「?」を縦の中央でそろえる）、送るボタンは `partials/modal-submit` で出す。ボタンの名前を、画面ごとに書かない（`App\Support\ModalMode::SUBMIT_LABELS`）。
  ```blade
  <div id="…-modal" class="blog-switch-modal site-modal" data-modal-mode="edit">
      <div class="blog-switch-dialog">
          @include('partials.modal-title', ['title' => '…', 'tip' => '…'])
          …
          @include('partials.modal-submit', ['mode' => 'edit'])
  ```
* アイコンは、ヘッダーのお知らせ・ログアウトのアイコンと同じ枠で囲む。動き（光・流れる電気）は付けない。
* アイコンに乗せると、ツールチップでモードの名前（新規・編集・切替・情報・削除・ゴミ箱へ移動）を出す（1-1。`App\Support\ModalMode::ICON_LABELS`。D-108-01）。
* 同じポップアップをモードを変えて開くときは、開く要素に `data-modal-mode` を付ける（アイコンとボタンの名前が切り替わる）。
* 削除のモードは、消すものの確認（説明・名前の入力・チェックなど）をポップアップの中に出し、送るボタン「削除」とキャンセルを並べる。送るボタンの見た目は、ほかのモードと同じ（赤枠の `btn-danger` にしない。D-120-01）。
* ゴミ箱へ移動のモードは、WordPress のゴミ箱へ移す（元に戻せる）確認に使い、完全に消す削除のモードと分ける。確認の出し方と送るボタンの見た目は、削除のモードと同じ（送るボタン「ゴミ箱へ移動」とキャンセルを並べる。D-123-01）。
* 削除のモードのアイコンの×だけは赤にする（ごみ箱は、ほかのアイコンと同じ色。blank：`public/css/blogos.css`、ironman：`components/header.css` の `.modal-icon-cross`。D-123-01）。
* 送るボタン以外のボタン（接続確認・解除・閉じる・キャンセルなど）は、モードで変えない。
* 新規のポップアップの題名に「～を登録」を付けない（アイコンとボタンで分かるため。例：「ブログ」）。切り替えるポップアップの題名は「～切替」（ブログ切替・テーマ切替）。メニューの項目の名前は、これまでどおり（D-100-04）。
* 種類を示すアイコンは、モードのアイコンの右に、同じ枠で出す。今は定期実行（カレンダーと時計）だけ。`@include('partials.modal-title', ['title' => …, 'kindIcon' => 'schedule'])`。種類のアイコンを出すポップアップは、題名に種類（「（定期実行）」など）を付けない（D-103-01）。

## 4-3. 有効のチェックと設定値

* 有効・無効を決めるチェックがあるポップアップは、有効のチェックを一番上に置き、その下に設定値を並べる。チェックの名前は「有効」にそろえる（例：定期実行、音声操作）。定期実行は「有効 → 設定値 → 次回実行 → 前回実行」（D-103-02・D-107-01）。
* 有効のチェックを外すと、その有効で使われる設定値を押せなくし、薄く出す。チェックを入れると押せるように戻す。設定値の中にさらに有効のチェックがあるときは、上のチェックが外れていれば、下のチェックとその設定値も押せない（例：記事の再評価の「診断の後の編集案の作成」）（D-103-03・D-103-04）。
* 有効と関係なく使われる設定値（例：全ブログ共通の時刻を、ブログごとの有効と同じポップアップで決めるもの）は、押せるままにする（D-103-03）。
* 書き方：チェックに `data-enable-switch="名前"`、押せなくする部分に `data-enabled-by="名前"`（`layouts/header` の JavaScript）。押せなくした欄も、送るときに戻して送る。画面を出した時点で押せない欄（例：音声操作の、まだ使えない方式）は、有効でも押せないままにする（D-107-02）。

## 4-4. ボタンのアイコン（押すと何が変わるか）

* 送るボタンの名前の左に、押すと何が変わるかのアイコンを付ける（画面の中のボタンも、ポップアップの送るボタンも。D-121-01）。

| アイコン | 付けるボタン | 例 |
| --- | --- | --- |
| WordPress（外の輪と、W をくり抜いた円） | 押すと WordPress を変える（反映が成功すると、BlogOS の DB も合わせて更新する） | WordPressへ反映する・完全に削除する・ゴミ箱へ移動する・選んだものを公開する |
| BlogOS（アークリアクター） | 押すと BlogOS の中だけを変える（WordPress は変えない） | 保存する・登録する・確認待ちにする・AI の実行・今すぐ同期 |
| 付けない | どちらも変えない | 絞り込む・取得（GET のフォーム）・ログイン・閉じる・キャンセル・確認の画面を開くだけのリンク（反映の確認へ） |

* 書き方：ボタンの開始タグのすぐ後ろに `@include('partials.button-icon', ['to' => 'wordpress'])`（BlogOS は `'blogos'`）。ポップアップの送るボタンは `partials/modal-submit` が付ける（WordPress を変えるポップアップを作るときは `'submitIcon' => 'wordpress'` を渡す）。種類とツールチップは `App\Support\ButtonIcon`。
* 色はボタンの文字の色（主な操作は金、赤枠のボタンは赤）。大きさは文字に合わせる。アイコンに乗せると、ツールチップで意味を出す（1-1）。
* 送るボタンを足すときは、どちらを変えるかを決めて、アイコンを付ける（付けないのは、どちらも変えないボタンだけ）。
* ボタンの名前は、アイコンとは別に決める（名前の言葉のそろえ方は、5章の「ボタンの言葉と色」）。

## 4-5. 削除・取り消せない操作のボタンの見た目

* 削除のボタン（削除・完全に削除する・ゴミ箱へ移動する・この～を削除する）と、削除ではない取り消せない操作のボタン（破棄する・取り消す・接続を解除・解除）は、主な操作のボタンと同じ見た目にする（ironman：金の縁取りと赤）。ポップアップの削除のモードの送るボタン（4-2）とそろえる（D-122-01・D-122-02）。
* 赤枠の `btn-danger` は使わない（CSS からもなくした）。
* 操作の重さは、ボタンの色ではなく、押す前の確認（名前やスラッグの入力・チェック・ブラウザの確認）で伝える。
